Prérequis et préparation
⏱️ ~15 minutes 📋 Installation des outils

Installer les outils requis

macOS (Homebrew) 
# Installer les outils nécessaires
$ brew install awscli        # AWS CLI v2
$ brew install terraform     # Terraform 1.5+
$ brew install node          # Node.js 20+
$ brew install git           # Git
$ brew install jq            # JSON processor
# + Docker Desktop depuis docker.com

Vérifier les versions

Vérifications 
$ aws --version          # aws-cli/2.x.x
$ terraform --version    # Terraform v1.5+
$ node --version         # v20.x.x
$ docker --version       # Docker version 24+
$ git --version          # git version 2.x

Créer un utilisateur IAM temporaire

Le bootstrap initial nécessite un utilisateur IAM avec des permissions administrateur.

  1. Aller dans AWS Console → IAM → Users → Create user
  2. Nom : terraform-bootstrap
  3. Attacher la policy AdministratorAccess
  4. Créer des Access Keys (CLI)
  5. Notez la AWS_ACCESS_KEY_ID et la AWS_SECRET_ACCESS_KEY
🔒
Sécurité
Cet utilisateur est temporaire. Après la mise en place d'OIDC (étape 7), vous supprimerez ces clés. Les pipelines CI/CD utiliseront OIDC, sans aucune clé permanente.
✓
Checkpoint — Outils installés
AWS CLI, Terraform, Node.js, Docker et Git sont installés et fonctionnels.
4
Bootstrap Terraform — Remote State
⏱️ ~5 minutes 🗄️ S3 + DynamoDB

Pourquoi un bootstrap ?

Terraform stocke l'état de l'infrastructure dans un fichier terraform.tfstate. Le remote state le stocke dans S3 (avec versioning et chiffrement) et utilise DynamoDB pour le locking.

Bootstrap 
# Aller dans le dossier bootstrap
$ cd terraform/bootstrap

# Initialiser Terraform
$ terraform init
Initializing the backend...
Terraform has been successfully initialized!

# Prévisualiser les changements
$ terraform plan
Plan: 5 to add, 0 to change, 0 to destroy.

# Appliquer (tapez 'yes')
$ terraform apply
Apply complete! Resources: 5 added.

# Vérifier
$ aws s3 ls | grep taskmanager-terraform-state
$ cd ../..
✓
Checkpoint — Remote state prêt
Bucket S3 et table DynamoDB créés. Terraform peut stocker son état de manière sécurisée.

14
Nettoyage et destruction du LAB
⏱️ ~15 minutes 🧹 Nettoyage complet
⚠️
Ordre de destruction important
Suivez l'ordre ci-dessous pour éviter les erreurs de dépendances. Ne sautez pas d'étapes.
Destruction complète 
# 1. Vider le bucket S3 frontend
$ aws s3 rm s3://$BUCKET_NAME --recursive

# 2. Supprimer les images ECR
$ aws ecr batch-delete-image \
  --repository-name taskmanager-backend \
  --image-ids "$(aws ecr list-images --repository-name taskmanager-backend \
  --query 'imageIds[*]' --output json)"

# 3. Détruire l'infrastructure (~10-15 min)
$ cd terraform/environments/dev
$ terraform destroy
Tapez 'yes' pour confirmer

# 4. (Optionnel) Détruire le remote state
$ cd ../../bootstrap
$ terraform destroy

# 5. Supprimer l'utilisateur IAM temporaire
$ aws iam delete-user --user-name terraform-bootstrap
✓
Checkpoint — LAB nettoyé
Toutes les ressources AWS sont supprimées. Aucun coût ne continuera à être facturé.
